# Field Lessons（实战教训）

> 本项目在单用户生产环境真实运行数周，以下每条教训都对应一次真实故障或缺陷，
> 并已转化为机制修复。它们比设计文档更值钱——因为都是**用故障换来的**。

## L1. 提取管道 6 天零产出：水位线推进 bug

- **现象**：每日提取 cron 连续 6 天「正常执行」但零候选产出
- **根因**：单批取 30 条 + 水位线推进到**全表最大时间戳**——每轮只扫窗口内最早 30 条（反复扫已提取过的旧消息），水位线却已跳到全表末尾，中间几百条消息**永久丢失**
- **修复**：分批循环 + 水位线 = **本批最大**（非全表 MAX）；LLM 失败的批次不推进水位线（下轮重扫）
- **教训**：`进程活着 ≠ 在提取`，`水位线在动 ≠ 有产出`。管道必须有产出探针（见 L2）

## L2. 探针盲区：进程活着 ≠ 在提取

- **修复**：健康告警增加产出探针——近 7 天无候选产出即告警，且探针必须在 cron 数据库访问**之前**执行（DB 异常不能连探针一起拖垮）

## L3. 提升 ↔ 挤出跨轮震荡

- **现象**：达标详情条目被挤出后，下轮又因「常驻无同源」被提升回来——循环动作、日志噪音
- **修复**：双保险——①挤出落盘条目 30 天冷却期不提升；②挤出第一段排除「高价值同源条目」（其详情已达标可提升）
- **教训**：自动化的稳态分析要跨轮看，不能只看单轮正确

## L4. 纯 LRU 挤出误伤行为规则

- **事故**：常驻画像文件超配额后按「文件靠后」挤出，把两条**高频行为规则**（影响每轮对话的偏好）挤出了常驻区——信息没丢（落盘详情层），但**行为退化**了
- **修复**：回滚 + 人工挑选低影响条目；挤出排序引入「行为影响」维度（高价值保护）
- **教训**：挤出排序的判据必须反映「离开常驻的代价」，不能只反映「文件位置」

## L5. 活跃记忆被误归档：last_verified 不刷新

- **现象**：被频繁合并（UPDATE）的记忆 `last_verified` 停留在创建日 → 90 天一到被复核门标 dormant → 下轮归档
- **结果**：**越活跃的记忆死得越快**，与设计意图完全相反
- **修复**：每次 UPDATE 刷新 `last_verified`；标 dormant 时同时刷新复核日（给足观察期）

## L6. LLM 决策的 target 被丢弃

- **现象**：LLM 输出「与条目 B 冲突」，代码却对相似度最高的条目 A 执行失效
- **修复**：优先采用 LLM 指定的 target slug，匹配不到才回退相似度排序
- **教训**：这条缺陷被两个独立审查者同时命中——**独立互查的价值**（本项目的审查流程：编写方 → fixture 测试 → 独立 agent 审查 → 修复 → 复验）

## L7. dry-run 也写日志，破坏幂等

- **现象**：dry-run 预演时把 fingerprint 写入幂等表 → 真实执行时全部跳过
- **修复**：dry-run 不落任何日志/表/目录

## L8. 候选饥饿：截断先于去重

- **现象**：候选列表先截断前 8 条、再过滤已处理 → 已处理的占住位置，后面的候选永远轮不到
- **修复**：先过滤已处理，再取前 N

## L9. 时区异常被吞，告警永失效

- **现象**：naive 与 aware 时间相减抛 TypeError，被 `except Exception: pass` 吞掉 → 「>7 天未运行」告警永远不触发，「无触发」是数据巧合不是逻辑在跑
- **教训**：**裸 except 吞异常 = 功能静默失效**。探针修复后必须用边界用例回归（构造 10 天前的数据验证告警真的会响）

## L10. 测试先疑己

本项目的 4 套 fixture 测试在开发期多次「失败」，最终归因全是**测试脚本自身**的错误：
- 断言里引用未 import 的模块
- 无效断言（`assert X if False else True`）
- 断言路径与实现行为不符（未读实现细节就写预期）
- **纪律**：断言失败先怀疑断言，再怀疑被测代码；测试必须覆盖「新修复的行为」而不是只测旧行为

## L11. Windows 反斜杠被转义损坏文件

- **事故**：文本替换工具把含 `\r` 的 Windows 路径替换进 CRLF 文件 → 文件损坏
- **纪律**：含反斜杠的替换用字节级验证（repr 对比），改后 grep 复核

## L12. kill 后台进程后，子进程仍在写交付物

- **事故**：终止 CLI 主进程后，其子进程继续写输出文件 8 分钟——交付物在「验收后」又被更新
- **纪律**：验收前检查产物 mtime；kill 后等待文件稳定再验收

## L13. LLM 输出解析的脆弱点

- `str.format` 撞 JSON 花括号 → KeyError（用 `replace` 代替）
- LLM 输出非法动作值 → 静默落入 NOOP 丢弃候选（改为校验 + 回退规则）
- LLM 全挂时评测「样本不足」被当作 PASS（改为样本 ≥3 才可判）

## L14. 相似 ≠ 矛盾

- **事故**：相似度 0.45 即「替换」——互补的、更详细的行为规则被弱版本整条替换
- **修复**：同义（包含关系或 ≥0.8）才替换；替换是整块（§ 分块）不是子串
- **教训**：**相似度是相似度，矛盾是矛盾**——没有对立语义检测的冲突处理会误伤信息

## L15. 公共基建的复制漂移

- 四个脚本各抄了一份 frontmatter 解析/原子写/LLM 封装，出现行为漂移（有的处理 BOM、有的不处理）
- **教训**：重复三次以上就该抽公共模块（这是本项目的已知技术债，重构排在路线图）

---

*每一轮审查（独立 agent ×2）平均发现 10-20 个真实缺陷；其中约 1/3 是「门失效级」——
不修会让整套机制从第一天就跑偏。多轮独立审查不是流程仪式，是本项目质量的主要来源。*
