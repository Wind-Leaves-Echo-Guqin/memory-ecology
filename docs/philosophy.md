# Design Philosophy（设计哲学）

> 本文是 Memory Ecology 全部机制的设计锚点。任何一条机制若违反以下原则，即为设计缺陷。

## 起源

本项目始于一个单用户的真实痛点：Agent 的常驻记忆文件**反复写满**（占用率长期 95%+），
写入靠模型自觉（已被实证不可靠），只进不出，新旧混淆，无法回溯。简单方案（扩容上限、
一次性人工瘦身、接入外部记忆服务）都被否决——它们治标不治本，且违背一个更深的信念：

> **进化是目的，管理是手段。**

记忆不是静态库存，是一个**有生有死的生态**。系统的职责不是替用户记住一切，而是让记忆
像生态一样：入口松、出口紧、有竞争、有淘汰、有遗传、可追溯。

## 九条原则

### 1. 进化是目的，管理是手段

记忆与技能应当持续**繁殖、竞争、取代、遗传**（血缘链 `evolved_from`）。合并（2→1，亲代
消失）是治理；繁殖（2→3，亲代保留）是进化。进化的判据是生态位取代，不是人工指令。

### 2. 用户维护负担 = 零

系统必须自洽运行：年度确认可跳过、月度报告可不看、阈值默认值自动生效。**「确认」是可选
的覆盖（override），不是义务。** 凡是依赖用户定期行动的方案都是失败方案——用户无法保证
及时维护。

### 3. 规则驱动 + 保守阈值 + 可逆兜底；自动化 ≠ 统计校准

单用户的数据量撑不起统计校准（样本不足时校准比不校准更糟）。因此一切判定用**确定性规则**
（事件计数、时间跨度、类型、字符串比对），阈值取保守默认值并自动生效。统计校准只是数据
充足后的优化，不是运行前提。

### 4. 一切可回滚

撤销能力决定修改自由度。git 每日快照 + 操作日志 + quarantine 三保险。**物理删除在代码层
禁用**——只有 `superseded` 标记与隔离区移动，永远保留恢复路径。正确性交给「可撤销」而非
「阈值准」。

### 5. 机制优先于协议

凡被证明不可靠的环节（如「靠模型自觉写记忆」）一律机制化：cron 管道、状态机、探针、
健康双保险。规则必须落到可校验的载体（脚本/字段/清单），不新增「自觉仪式」。

### 6. 组合优于堆叠

一味的堆叠不如学会组合：依赖声明（requires）、枢纽技能（hub）、任务路由。重叠的判定：
知识重叠（同源）→ 合并；功能重叠（异构）→ 保留（冗余是稳定性的保险）。

### 7. 保护区

生态需划保护区：核心 / 缓冲 / 实验三级。划分以用户显式指定为主，隐式通道（依赖枢纽、
通用度）为辅。保护区**免疫结构动作，不免疫内容更新**——防止「僵尸技能」在保护区内腐烂。

### 8. 人类记忆模型

偶然 → 短期；反复 → 长期；程序经验经「操作 → 凝练 → 总结」成技能。**巩固层**是关键：
一次事件不直接写入常驻，需跨会话重复达到阈值才提升。

### 9. 自洽运行

系统不依赖用户在场。证据与标记自动前进，执行按钮可延期且跳过无害；一切阈值默认值自动
生效，拍板只是覆盖。**低干预不是目标，是成熟态**：建设期用户多拍板，成熟期近零干预，
唯一必须人工的机制是保护区年度审查。

## 隐喻映射的纪律

生态学概念映射到工程实现必须过四道关：**功能**（对应什么机制）、**对应**（落在哪个组件）、
**实现**（如何计算）、**属性完整性**（被映射概念的关键属性是否都保留）。例如「种子有寿命」
→ 休眠池条目必须设长眠待查；「扰动后有演替」→ 环境切换后先长轻量通用技能。映射不完整
的隐喻只是叙事，不是设计。
